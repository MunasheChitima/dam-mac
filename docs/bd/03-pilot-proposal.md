# Canva/Pexels product proof

## Product

This proof is for **dam-mac**: a macOS DAM with a custom visual indexing engine.

It is not a FindandSeek demo and it is not a document-memory demo.

## Goal

Show Canva what dam-mac already does in visual-library terms:

- index images and visual assets cheaply
- retrieve the right existing asset quickly
- let people start creating from what they already have
- reduce unnecessary generation

## Thesis

Many visual creation requests are retrieval problems, not generation problems.

If Canva can help a customer find the right existing asset fast enough, the
customer may never need to generate a new one. That is the behavior dam-mac was
built to support.

## Proof shape

Demonstrate the product against a narrow, representative visual corpus:

- a curated set of Pexels images or videos
- a sample brand or campaign library
- realistic prompts from design and marketing workflows

The proof should show the product itself, not a hypothetical future integration.

## Example corpus

A practical proof corpus could include:

- 10,000 to 50,000 images from a selected Pexels subset
- a sample brand library with logos, campaign visuals, product shots, and templates
- a prompt set based on real "I need a visual for this" requests

## Scenarios to demonstrate

1. "Find me something like the hero image from our summer campaign."
2. "Give me an approved product image for a social post about [theme]."
3. "Start from our own assets instead of generating a new image."
4. "Find a Pexels asset that fits this campaign look."
5. "Show the best existing visual across our library and Canva-owned stock."

## Success metrics

### Primary metrics

- **retrieval hit rate**: how often an acceptable existing visual is found before
  generation is needed
- **avoided generation rate**: share of requests that would otherwise have gone
  to generation
- **asset reuse rate**: increase in reuse of customer-owned or Canva-owned visuals

### Secondary metrics

- time to a satisfactory first result
- whether the user can start from their own library
- how often generation is still the right next step

### Economic metrics

- estimated avoided generation calls
- estimated reduction in AI spend on those workflows
- increased use of inventory Canva already owns or hosts for customers

## Evaluation method

For each prompt in the test set:

1. show the current path: search, then generate
2. show the dam-mac path: retrieve from existing visual library first
3. record whether an acceptable asset was found without generation
4. record when generation was still the better answer

At the end, summarize:

- where creating from existing assets clearly wins
- where generation remains necessary
- what Canva's customers would gain if this capability lived in their product

## How to offer it

Offer the product, not a connector trial:

> We have already built a visual DAM around this behavior. We would love to show
> you what it does on a representative content slice and see whether that value
> belongs with Canva.

## If they want it

If the proof is positive, the conversation can move to how Canva takes the
value on:

- bringing the visual indexing capability into Canva's offering
- giving enterprise customers a stronger way to create from their own assets
- applying it to Pexels and customer libraries Canva already has
- commercial terms that follow from that

Do not lead with acquisition language. Lead with the product and the customer
value.
