# Blackmagic Design / DaVinci Resolve BD note

## Are they Australian?

Yes.

Blackmagic Design, the company behind DaVinci Resolve, is an Australian company
headquartered in South Melbourne, Victoria.

## Why they are interesting

DaVinci Resolve already sits inside a workflow where large visual libraries have
to be searched, organized, and reused:

- editors work from large media pools
- teams manage footage, stills, campaign assets, and archives
- Blackmagic already offers collaboration through Blackmagic Cloud
- Resolve 21 already includes AI-powered media search such as IntelliSearch

That means the pitch is **not** "you need AI search." They already have it.

The pitch has to be one of these:

- better retrieval and reuse across broader asset libraries
- stronger DAM behavior around owned and team media
- MCP-native access to media libraries for AI-assisted workflows beyond current
  in-product search

## Honest market read

### Where the fit is real

dam-mac overlaps with DaVinci Resolve around:

- visual asset retrieval
- reuse of existing media
- reducing time spent hunting through libraries
- creating from owned media before creating something new

### Where we should not overclaim

Blackmagic already has:

- sophisticated post-production software
- built-in AI-assisted media analysis and search
- cloud collaboration around project libraries and media

So the pitch is not "we invented media search." The pitch is:

> We built a visual DAM with an MCP-native indexing engine that may extend the
> value of your existing media workflows, especially where broader asset reuse
> and AI-assisted library access matter.

## Best angle

Lead with **media-library intelligence for professional workflows**.

For Blackmagic, the message is less about saving frontier-model costs and more
about:

- helping professionals get to the right media faster
- making existing footage and stills more reusable
- connecting library intelligence to AI-assisted tools and workflows
- strengthening the media-management side of the workflow, not only the edit

## Buyer personas

Prioritize:

1. product leadership for DaVinci Resolve
2. media management / collaboration / cloud workflow leadership
3. AI / DaVinci Neural Engine leadership
4. strategy or partnerships leadership

## Suggested pitch

Use this framing:

> We built dam-mac as a DAM product with a custom indexing engine for image and
> content libraries. The value is simple: help people find, reuse, and create
> from the assets they already have. Because it is already MCP-native, it also
> pairs naturally with AI-assisted workflows that need to retrieve the right
> media first.

Then adapt it to Blackmagic:

> We think that capability may be relevant to Blackmagic because DaVinci Resolve
> already lives in a world of large media pools, collaboration, and AI-assisted
> workflows. We are not pitching generic AI search. We are pitching stronger
> media-library intelligence and reuse.

## What not to say

Avoid:

- "you need search"
- "you should enter DAM"
- "we can replace IntelliSearch"
- "this is mainly about saving your AI bill"

Those are the wrong hooks for Blackmagic.

## What to say instead

Use:

- "media-library reuse"
- "broader asset intelligence"
- "professional workflow efficiency"
- "AI-assisted retrieval of existing media"
- "MCP-native access to library intelligence"

## Sample outreach email

Subject: A visual DAM capability that may fit Resolve's media workflows

Hi [Name],

We built dam-mac, a DAM product with a custom visual indexing engine for image
and content libraries. The product helps people find, reuse, and create from

defaulting to new generation.

I thought of Blackmagic because DaVinci Resolve already sits inside large-media

our DAM and indexing capability may extend the value of that workflow,

Because the product is already MCP-native, it also pairs naturally with modern
AI-assisted workflows that need to retrieve the right existing media first.

If useful, I would love to show you what we have built and see whether it is
relevant to Blackmagic's direction.
